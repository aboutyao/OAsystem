# 企业级 OA 系统开发落地计划

## 1. 文档定位

本文档基于 `OA_SYSTEM_DESIGN.md` 编写，用于把系统设计转化为可执行的开发计划。

本项目按最终完整版本开发，不采用精简 MVP 或功能分期交付。开发过程可按工程依赖顺序推进，但最终交付范围以完整企业级 OA 平台为准。

## 2. 开发目标

最终系统需要完整交付：

- 认证与账号安全
- 组织人员中心
- 权限中心
- Flowable 流程审批引擎
- 规则配置中心
- 表单中心
- 消息与待办中心
- 通知公告
- 请假、报销、用章、采购、合同
- 会议室、固定资产、办公用品
- 文件资料库
- 报表统计
- 导入导出
- 打印模板与二维码核验
- 审计日志与异常中心
- 运维监控与备份恢复
- Web 响应式体验

## 4. 技术栈确认

推荐技术栈：

```text
前端：Vue 3 + TypeScript + Vite + Pinia + Vue Router
UI：Element Plus 或 Ant Design Vue
后端：Java 17+ + Spring Boot + Spring Security + Flowable
数据库：MySQL 8.x 或 PostgreSQL
缓存：Redis
部署：Nginx + 后端服务 + 数据库 + Redis + 文件存储
```

编码前需要最终确认：

- 数据库使用 MySQL 还是 PostgreSQL。
- UI 组件库使用 Element Plus 还是 Ant Design Vue。
- 后端 ORM 使用 MyBatis-Plus 还是 JPA。
- 文件存储第一版使用本地目录还是对象存储。
- 认证使用 JWT、Session，还是混合方案。

## 6. 开发推进顺序

### 6.1 基础工程

目标：搭建可运行的前后端基础工程。

任务：

- 初始化前端工程。
- 初始化后端工程。
- 配置代码格式化和基础规范。
- 配置数据库连接。
- 配置 Redis。
- 配置统一返回体。
- 配置统一异常处理。
- 配置日志和 `requestId`。
- 配置基础路由和布局。

验收：

- 前端可启动并访问基础页面。
- 后端健康检查接口可访问。
- 后端可连接数据库和 Redis。
- 接口异常返回格式统一。

## 7. 横向规范

### 7.1 后端规范

- Controller 只做参数接收和返回。
- 业务规则放在 Service。
- 跨模块编排放在应用服务。
- 所有列表接口必须分页。
- 所有写操作必须记录操作人和时间。
- 关键状态变更必须事务处理。
- 关键操作必须幂等。
- 所有业务错误使用稳定错误码。

### 7.2 前端规范

- 页面按业务域拆分。
- API 调用统一封装。
- 权限指令控制菜单和按钮显示。
- 表格支持分页、筛选、重置。
- 表单支持校验和草稿。
- 错误、空状态、加载状态统一。
- 移动端优先保证待办、审批、消息、公告可用。

### 7.3 安全规范

- 不信任前端传入权限字段。
- 附件下载必须后端鉴权。
- 导出必须校验数据权限。
- 审批必须校验当前任务处理人。
- 敏感字段脱敏。
- 高危操作二次确认。
- 审计日志不可由普通管理员删除。

## 9. 里程碑验收

## 10. 风险控制

| 风险 | 控制方式 |
| --- | --- |
| 需求不断变 | 编码前冻结最终范围，变更进入评审 |
| 流程过复杂 | 先建立流程用例集，再配置 Flowable |
| 权限越权 | 后端统一校验，权限测试覆盖 |
| 历史数据混乱 | 保存快照和版本 |
| 重复提交 | 幂等键、乐观锁、事务 |
| 附件泄露 | 附件统一鉴权下载 |
| 报表争议 | 提前定义统计口径 |
| 最后集成风险大 | 内部里程碑持续联调 |
| 周期失控 | 按依赖顺序推进，关键底座优先完成 |
