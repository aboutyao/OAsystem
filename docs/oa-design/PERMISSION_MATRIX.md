# 企业级 OA 系统权限矩阵

## 1. 文档定位

本文档基于 `OA_SYSTEM_DESIGN.md`、`DATABASE_DESIGN.md`、`API_DESIGN.md` 编写，用于定义企业级 OA 系统最终版本的权限模型和权限矩阵。

本文档用于指导：

- 后端接口鉴权
- 前端菜单和按钮显示
- 数据权限过滤
- 字段权限控制
- 附件权限控制
- 导出权限控制
- 审批权限校验
- 审计日志范围

核心原则：

- 前端负责体验层显隐，后端负责最终强校验。
- 菜单权限、按钮权限、数据权限、字段权限、附件权限、审批权限必须分离。
- 能查看数据，不代表能审批数据。
- 能查看单据，不代表能下载附件。
- 能配置流程，不代表能发布流程。
- 高危操作必须单独授权并写审计日志。

## 2. 权限模型

### 2.1 权限维度

系统权限分为以下维度：

| 权限维度 | 说明 |
| --- | --- |
| 菜单权限 | 控制用户能否进入某个页面 |
| 按钮权限 | 控制新增、编辑、删除、导出、发布、审批等操作 |
| 接口权限 | 控制后端 API 是否可调用 |
| 数据权限 | 控制用户能看到哪些业务数据 |
| 字段权限 | 控制字段是否可见、可编辑、必填、脱敏 |
| 附件权限 | 控制附件预览、下载、删除 |
| 审批权限 | 控制用户是否为当前任务处理人 |
| 临时授权 | 指定时间范围内临时授予某些权限 |

### 2.2 角色与权限关系

```text
用户
  ├── 所属部门
  ├── 岗位
  ├── 职级
  ├── 直属上级
  ├── 角色集合
  └── 临时授权

角色
  ├── 菜单权限
  ├── 按钮权限
  ├── 数据权限
  ├── 字段权限
  └── 附件权限
```

### 2.3 数据权限范围

| 数据范围 | 编码 | 说明 |
| --- | --- | --- |
| 仅本人 | `SELF` | 本人发起、本人处理、本人相关 |
| 本部门 | `DEPT` | 当前主部门数据 |
| 本部门及下级 | `DEPT_AND_CHILD` | 当前部门与子部门数据 |
| 指定部门 | `CUSTOM_DEPT` | 管理员配置的部门范围 |
| 指定人员 | `CUSTOM_USER` | 管理员配置的人员范围 |
| 全公司 | `ALL` | 全部数据 |
| 动态业务范围 | `DYNAMIC` | 根据发起、审批、抄送、责任人、保管人等关系判断 |

## 6. 数据权限矩阵

### 6.1 默认数据范围

| 角色 | 默认数据范围 | 说明 |
| --- | --- | --- |
| 超级管理员 | `ALL` | 全部数据 |
| 系统管理员 | `ALL` | 系统管理数据为主，业务数据可按配置 |
| 流程管理员 | `ALL` 或 `DYNAMIC` | 查看流程运行和异常，业务字段可限制 |
| 规则管理员 | `ALL` | 查看规则配置，不默认查看敏感业务附件 |
| 人事管理员 | `CUSTOM_DEPT` / `ALL` | 人事范围内数据 |
| 财务管理员 | `CUSTOM_DEPT` / `ALL` | 财务范围内报销和付款数据 |
| 行政管理员 | `CUSTOM_DEPT` / `ALL` | 行政范围内公告、用章、资产等 |
| 合同管理员 | `CUSTOM_DEPT` / `ALL` | 合同业务数据 |
| 审计人员 | `ALL` | 查看审计和授权业务数据，只读 |
| 企业领导 | `CUSTOM_DEPT` / `ALL` | 按授权范围查看 |
| 部门负责人 | `DEPT_AND_CHILD` | 本部门及下级 |
| 普通员工 | `SELF` | 本人相关数据 |

### 6.2 业务数据可见规则

一条业务单据对用户可见，如果满足任一条件：

- 用户是单据创建人。
- 用户是当前审批人。
- 用户处理过该单据。
- 用户被抄送。
- 用户在该业务模块拥有数据范围权限。
- 用户是附件或文件的授权访问人。
- 用户是流程管理员且在流程异常处理场景中查看。
- 用户是审计人员且具备对应审计查看权限。

### 6.3 数据权限过滤字段

业务表必须保留：

- `created_by`
- `created_dept_id`
- `status`
- `process_instance_id`
- `created_at`

审批相关查询需要关联：

- `wf_task.assignee_id`
- `wf_task_record.operator_id`
- `wf_cc_record.receiver_id`
- `msg_message.receiver_id`

## 8. 附件权限矩阵

### 8.1 附件操作权限

| 操作 | 权限要求 |
| --- | --- |
| 上传附件 | 有单据编辑权限或当前节点允许上传 |
| 预览附件 | 有单据查看权限且附件字段可见 |
| 下载附件 | 有附件下载权限，且数据权限通过 |
| 删除附件 | 草稿创建人或模块管理员，已审批附件不建议删除 |
| 替换附件 | 业务允许且记录版本 |
| 查看下载日志 | 模块管理员、审计人员 |

### 8.2 敏感附件

敏感附件包括：

- 合同正文
- 发票
- 银行账户证明
- 个人证明材料
- 重要用章文件
- 内部制度文件

要求：

- 下载必须写日志。
- 不允许公开 URL 直接访问。
- 可配置水印。
- 可配置只预览不可下载。
- 审计人员查看也需要授权范围。

## 9. 审批权限规则

审批动作必须满足：

- 用户已登录。
- 用户拥有审批接口权限。
- 用户是当前任务处理人，或具备流程管理员干预权限。
- 任务状态为 `PENDING`。
- 流程实例未结束。
- 单据状态允许审批。
- 幂等键未被重复使用。

特别说明：

- 领导能查看全公司数据，不代表能审批所有任务。
- 流程管理员能干预流程，但正常审批动作仍应优先由当前审批人处理。
- 审批人转交后，原审批人不能继续处理该任务。
- 或签节点被他人处理后，其他审批人的任务应取消或跳过。

## 11. 临时授权规则

临时授权用于短期代理或特殊处理。

要求：

- 必须设置开始时间和结束时间。
- 必须填写授权原因。
- 到期自动失效。
- 可提前撤销。
- 授权、撤销、到期都要写审计日志。
- 临时授权不能超过授权人自身权限。
- 超级管理员权限不允许通过临时授权授予。

适用场景：

- 人员休假期间临时代理审批。
- 财务临时协助处理某类报销。
- 审计临时查看某个时间段数据。
- 项目负责人临时查看项目相关采购和合同。

## 12. 前端权限控制

前端需要控制：

- 菜单显隐。
- 路由访问。
- 按钮显隐。
- 表格列显隐。
- 表单字段可见、只读、必填、脱敏。
- 附件操作按钮显隐。

但前端控制只用于体验，不能作为安全依据。

前端权限数据建议来自：

```http
GET /api/auth/me
GET /api/permission/users/{userId}/preview
```

## 13. 后端权限控制

后端必须控制：

- API 接口权限。
- 数据权限过滤。
- 字段权限过滤。
- 附件下载权限。
- 审批任务权限。
- 导出权限。
- 高危操作权限。

后端不得信任：

- 前端传入的用户 ID。
- 前端传入的数据范围。
- 前端隐藏的按钮状态。
- 前端传入的审批人身份。
- 前端传入的字段可见性。

## 14. 权限验收用例

### 14.1 基础用例

- 普通员工不能进入系统管理。
- 普通员工只能看到本人申请。
- 部门负责人能看到本部门及下级部门数据。
- 财务只能处理授权范围内报销数据。
- 行政只能管理授权范围内用章、资产、会议室。
- 审计人员只能查看，不允许修改业务数据。
- 无导出权限用户不能导出。

### 14.2 审批用例

- 非当前审批人不能审批。
- 当前审批人可以通过或驳回。
- 转交后原审批人不能继续审批。
- 或签节点一人通过后其他任务失效。
- 会签节点必须全部通过才进入下一节点。
- 审批人离职后流程管理员可转交。

### 14.3 附件用例

- 有单据查看权限但无附件下载权限时，不能下载附件。
- 抄送人只能查看授权字段和附件。
- 合同附件下载必须写日志。
- 敏感附件不允许通过公开链接访问。

### 14.4 字段用例

- 普通审批人查看报销时，收款账户脱敏。
- 财务可编辑实付金额和付款状态。
- 合同管理员可维护合同附件版本。
- 审计人员可查看授权字段，但不能编辑。

### 14.5 高危操作用例

- 修改角色权限写入审计日志。
- 发布流程版本需要流程发布权限。
- 发布规则版本需要规则发布权限。
- 批量导出需要导出权限并写日志。
- 停用账号需要二次确认。

## 15. 后续待细化

进入详细开发前，需要继续细化：

- 每个菜单的最终 `menuCode`。
- 每个按钮的最终 `permissionCode`。
- 每个接口对应的权限编码。
- 每个模块的数据权限 SQL 过滤策略。
- 每个业务表的字段权限清单。
- 每个附件字段的敏感级别。
- 高危权限审批流程是否启用。

## 16. 总结

权限设计的核心目标是既要方便日常办公，又要避免越权访问、越权审批和敏感数据泄露。

本系统采用多维权限模型：菜单权限控制入口，按钮权限控制操作，数据权限控制可见范围，字段权限控制字段展示和编辑，附件权限控制文件访问，审批权限控制流程动作。所有权限最终必须由后端强校验，前端只负责体验层显隐。
